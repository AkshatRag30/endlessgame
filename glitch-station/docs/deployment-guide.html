1How it is hosted

One Cloudflare Worker does everything. It serves the game page, creates rooms, and runs one small server (a Durable Object) per room.

AddressWhat answers it
/ and every other page pathThe built game client from apps/client/dist (static files served by the Worker)
/api/roomsCreates a room and returns its four letter code
/api/rooms/ABCDSays whether room ABCD exists
/ws?room=ABCDThe live game connection, handed to room ABCD's Durable Object
/healthReturns {"ok":true} so you can check the server is up

Because the page and the server live at the same address, the game finds its server automatically. That is why no configuration is needed. (The PRD planned Cloudflare Pages for the client; serving it from the Worker is Cloudflare's newer way to do the same thing, also free, and removes a whole deploy step.)

3The env file question

For the normal deploy, you do not need an env file at all. There are no secrets in this project.

There are two optional settings. Leave both alone unless you have a reason:

SettingWhere it livesWhen to use itExample
VITE_SERVER_URLA file you create: apps/client/.env.production (git ignores it)Only if you host the game page somewhere other than the Worker, for example on Cloudflare Pages or Netlify. It tells the page where the room server is.VITE_SERVER_URL=wss://glitch-station.yourname.workers.dev/ws
ALLOWED_ORIGINSapps/server/wrangler.jsonc, in "vars". Not secret, so it is fine in the file.To stop other websites from creating rooms or connecting to your server. Empty means allow any site."ALLOWED_ORIGINS": "https://glitch-station.yourname.workers.dev"

A template for the first one is in apps/client/.env.example. If you ever do add real secrets later (for example in Phase 8), use npx wrangler secret put NAME, never a committed file.

4Deploy step by step

Run these in a terminal inside the glitch-station folder.

  1. Install packages (first time only)npm install
  2. Check everything passesnpm run lint and npm test. Both should finish without errors (33 tests).
  3. Log in to Cloudflare (first time only)npx wrangler login opens your browser. Click Allow. Back in the terminal you will see "Successfully logged in". Check with npx wrangler whoami.
  4. Deploynpm run deploy. This builds the game page, then uploads the Worker, the page files and the Durable Object setup in one go. The first time, if your account has no workers.dev subdomain, Wrangler asks you to choose one.
  5. Copy your linkAt the end Wrangler prints something like https://glitch-station.yourname.workers.dev. That is your game. Share it with friends.
# the whole thing, first time
cd C:\Users\ACER\OneDrive\Desktop\endlessgame\glitch-station
npm install
npx wrangler login
npm run deploy

5Check it works

  1. HealthOpen https://glitch-station.yourname.workers.dev/health. You should see {"ok":true,...}.
  2. Automated smoke testnode scripts/smoke.mjs https://glitch-station.yourname.workers.dev creates a room, joins five headless players, starts a match and checks roles stay private. It ends with PASS.
  3. Load test (optional)Create a room in your browser, then node scripts/fake-players.mjs CODE 9 https://glitch-station.yourname.workers.dev fills it with nine network players. Note that this uses up free requests quickly (see limits).
  4. Real phonesOpen the link on two phones, ideally one on mobile data. Create a room on one, join with the code on the other. The ping pill should be green (under 150 ms).

6Updating the game

Change code, run npm run lint and npm test, then npm run deploy again. The link stays the same.

Deploying ends live matches. Room servers restart on deploy, so anyone mid match is disconnected and rooms in progress are lost. Deploy when nobody is playing.

To undo a bad deploy: npx wrangler rollback (run it inside apps/server), or pick an older version in the Cloudflare dashboard under your Worker's Deployments tab.

7Logs and analytics

The server writes one JSON line per event: room_created, join, match_started, elimination, meeting, vote_result, match_finished, disconnect, player_flagged and more. That covers the PRD section 14 analytics.

To seeDo this
Live log streamnpx wrangler tail glitch-station (from apps/server)
Past logs and searchCloudflare dashboard → Workers and Pages → glitch-station → Logs (observability is turned on in wrangler.jsonc)
Usage against free limitsDashboard → Workers and Pages → Overview, and the Durable Objects metrics on the Worker

8Free plan limits

On the Workers Free plan you are never charged. If a daily limit is hit, new operations of that kind fail until the reset at 00:00 UTC.

Limit (Durable Objects, free)AmountWhat it means here
Requests100,000 per dayJoining, room creation and WebSocket messages count. This is the one to watch.
Duration13,000 GB seconds per dayTime rooms are awake in memory. Rooms stay awake while anyone is connected.
StorageSQLite backed objects onlyRooms store almost nothing, so this does not matter.
Watch the message count. A player who is walking sends 20 movement messages a second; a standing player sends almost none. Cloudflare counts WebSocket messages toward requests, and may count them at a discount; check the pricing page for the current rule. Either way, a few friend groups playing in an evening is the realistic free ceiling. If you hit limits, the planned fix is to batch two movement steps per message (halves the count), and the PRD spend gate says only move to the Workers Paid plan (about 5 USD a month) once real groups prove they keep playing.

9Custom domain (optional)

If you own a domain on Cloudflare, add it to the Worker: Dashboard → glitch-station → Settings → Domains and Routes → Add → Custom domain, for example play.yourdomain.com. If you set ALLOWED_ORIGINS, add the new address there too and redeploy.

10Alternative: client on Pages

Only if you specifically want the page hosted separately:

  1. Deploy the server as usualnpm run deploy and note the Worker address.
  2. Point the client at itCreate apps/client/.env.production with VITE_SERVER_URL=wss://glitch-station.yourname.workers.dev/ws.
  3. Build and uploadnpm run build, then npx wrangler pages deploy apps/client/dist --project-name glitch-station-client.
  4. Lock it downSet ALLOWED_ORIGINS to your pages.dev address and deploy the server again.

11Troubleshooting

What you seeLikely cause and fix
You need to register a workers.dev subdomainPick one when Wrangler asks, or set it in the dashboard under Workers and Pages, then deploy again.
Not logged in or authentication errorsRun npx wrangler login again; check with npx wrangler whoami.
Error mentioning Durable Objects and the free planThe free plan only allows SQLite backed Durable Objects. The config already uses new_sqlite_classes; do not change that migration.
Deploy says the assets directory is missingUse npm run deploy from the project root (it builds first), not wrangler deploy on its own.
Page loads but "Could not create a room"Open /health. If that fails, the Worker did not deploy. If ALLOWED_ORIGINS is set, make sure it exactly matches the address in your browser bar (including https).
"That room does not exist"Rooms close after 10 minutes with nobody in them, and all rooms reset on every deploy. Create a new one.
Everything stopped working late in the dayProbably a free daily limit. Check usage in the dashboard; it resets at 00:00 UTC (5:30 AM in India).
High ping or rubber bandingCheck the ping pill. Over 300 ms usually means a weak mobile signal. Turn on Low effects on the home screen for older phones.
Phone on WiFi cannot open the local dev linkThat is the local setup, not deployment: allow Node.js through Windows Firewall on private networks.
